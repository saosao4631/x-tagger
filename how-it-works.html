1そもそも「拡張機能」とは何か

ブラウザ拡張機能(ブラウザエクステンション)は、Chrome などのブラウザに後から追加できる小さなプログラムです。特別な言語や専用ソフトは必要なく、ホームページを作るのと同じ HTML / CSS / JavaScript という3つの技術だけで作られています。

たとえるなら: ブラウザという「テレビ」に対して、拡張機能は後付けの「字幕装置」や「CMスキップ機能」のようなものです。テレビ本体(ブラウザ)を作り直すのではなく、映っている映像に横から手を加えます。

拡張機能の中身は、ただのファイルの集まりです。X Tagger も、フォルダの中に数個のテキストファイルが入っているだけです。その中で一番大事なのが manifest.json(マニフェスト=目録)という設計図のファイルです。ここに「この拡張機能の名前は何か」「どのサイトで動くのか」「何を許可してほしいのか」が書かれています。

// manifest.json(抜粋)— 拡張機能の設計図
{
  "name": "X Tagger",
  "permissions": ["storage"],           // データ保存を許可してほしい
  "content_scripts": [{
    "matches": ["https://x.com/*"],   // x.com のページで動く
    "js": ["statistics.js", "content.js"]
  }]
}

Chrome はこの設計図を読んで、「なるほど、この拡張機能は x.com のページで content.js というプログラムを動かし、データの保存機能を使いたいのだな」と理解し、その通りに動かしてくれます。

2なぜ他人のサイト(X)を書き換えられるのか

「Xは自分が作ったサイトじゃないのに、どうして勝手にツイートを消したりできるの?」— これが一番の疑問だと思います。カギは「Webページの正体」にあります。

Webページは、実は「組み立て説明書」

私たちが見ているXのタイムラインは、完成した1枚の画像ではありません。ブラウザがXのサーバーから受け取ったHTMLという設計図(部品の組み立て説明書)を、その場で組み立てて表示したものです。1つ1つのツイートは、次のような「部品(要素)」として組み立てられています。

<!-- Xのタイムラインの中身(イメージ)-->
<article data-testid="tweet">        ← ツイート1枚 = article という箱
  <div data-testid="tweetText">今日はPythonの勉強</div>
</article>
<article data-testid="tweet"> ... </article>   ← 次のツイート

この「組み立てられた部品の集まり」を DOM(ドム / Document Object Model) と呼びます。DOMはブラウザの中に置かれた「積み木の作品」のようなもので、JavaScript というプログラムから自由に触れます。積み木を1個抜いたり、色を塗ったり、新しい積み木を足したりできるのです。

ポイント: Xのサーバー(向こう側)は書き換えられません。でも、あなたのパソコンにいま表示されている積み木の作品(DOM)は、あなたのブラウザの中にあるので、拡張機能から触れます。X Tagger がしているのは「サーバーへの攻撃」ではなく、「手元に届いた作品の見た目を、自分好みに組み替える」ことだけです。

拡張機能は、ページの中に「同居」する

設計図(manifest)の content_scripts に登録されたプログラム(=コンテンツスクリプト、X Tagger では content.js)は、指定したサイトを開いた瞬間にそのページの中へ送り込まれ、ページと同じDOMを共有します。だからページ本体と同じように積み木(ツイート)を読んだり触ったりできる、というわけです。

3なぜツイートを「非表示」にできるのか

仕組みが分かれば、非表示は意外と単純です。ツイートを本当に削除しているのではなく、「見えないように隠している」だけです。

やっていることは「見えなくする印」を付けるだけ

CSS(見た目を決める言語)には display: none という命令があります。これは「この部品を画面から消して、無かったことにする」という意味です。X Tagger は、隠したいツイートに xt-hidden という目印(クラス)を付けるだけ。あらかじめ用意しておいたCSSが「その目印が付いた部品は消す」と決めているので、印が付いた瞬間に画面から消えます。

/* content.css — 「xt-hidden の印が付いた部品は消す」というルール */
.xt-hidden { display: none !important; }
// content.js — 広告だと判定したら、消す印を付ける(実際のコードの要点)
if (state.settings.hidePromoted && isPromoted(article)) {
  cell.classList.add("xt-hidden");   // ← これで画面から消える
  return;
}

広告やタグはどう見分けているのか

ツイートを消したり印を付けたりするには、まず「どれが広告か」「どれが興味のあるツイートか」を見分ける必要があります。X Tagger は主に2つの手がかりを使います。

  • 広告の判定: Xは広告ツイートを placementTracking という特別な部品で包む傾向があり、それを目印にします。加えて「プロモーション」「広告」「Ad」といった表示文字も手がかりにします。
  • タグの判定: ツイート本文(tweetText という部品)の文字を読み取り、あなたが登録したキーワードが含まれているかを調べます。含まれていれば、本文の上にPythonのような丸いチップ(これも新しく作った積み木)を差し込みます。
なぜ data-testid を目印にするのか: Xのデザイン上の名前(クラス名)は css-1dbjc4n のように自動生成されていて、頻繁に変わります。それを頼りにするとすぐ壊れます。一方 data-testid="tweet" はX自身がテスト用に付けている目印で、変更頻度が低いため、比較的長く使えます。それでもXの大改修で変わる可能性はあります。

「タグに合うものだけ表示」も同じ仕組み

フィルタモード(タグに一致しないツイートを隠す機能)も、原理は広告非表示とまったく同じです。「登録タグにも自動タグにも当てはまらないツイート」に xt-hidden の印を付けているだけです。だから「削除」ではなく「非表示」——設定を切れば元通り全部見えます。

4X Tagger の全体像 — 4つの登場人物

X Tagger は1つの大きなプログラムではなく、役割の違う4人の担当者が連携して動いています。それぞれ住んでいる「場所」が違うのがポイントです。

① content.js（Xのページの中に住む「現場担当」）
タイムラインを見張り、ツイートに印やチップを付け、隠し、本文の単語を数える。DOMに触れるのはこの人だけ。
▲ 数えた単語を報告 ／ ▼ 集計結果を受け取る
② background.js（ブラウザの裏で常駐する「集計の司令塔」）
複数のタブから届く「この単語を数えて」という報告を1つずつ順番に処理し、セットごとの集計を管理する。頻出語の自動タグ昇格もここが判断する。
▲ 設定・タグを読み書き ／ ▼ 集計を読み書き
③ chrome.storage（ブラウザ内の「金庫」）
タグ・設定・単語の集計を保存する場所。すべてあなたのパソコンの中。外部サーバーには一切送られない。
▲ 設定を保存 ／ ▼ 現在の設定を表示
④ popup.html / popup.js（ツールバーの「設定画面」）
アイコンを押すと開く画面。タグの登録・編集、セットの切り替え、頻出単語ランキングの表示、AI補助の操作を担当する。

この4人に加えて、共通で使う道具箱として statistics.js があります。「単語をどう正規化するか」「タグの内容が変わったかを表す“署名”をどう作るか」といった3人が共通で使う計算ルールをここにまとめ、①②④のどこからでも同じルールを呼べるようにしています。

なぜ「司令塔(background)」を分けたのか

Xは複数のタブで同時に開けます。もし各タブの現場担当(content.js)が金庫に直接書き込むと、タブAとタブBが同時に書いて片方の集計を上書きしてしまう事故が起きます。そこで、書き込みは必ず司令塔ひとりに任せ、届いた報告を順番待ちの列(キュー)にして1つずつ処理することで、上書き事故を防いでいます。

// background.js — 報告を1件ずつ順番に処理する「順番待ちの列」
let queue = Promise.resolve();
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  queue = queue.then(() => handle(message)) ...  // 前の処理が終わってから次を実行
});

51枚のツイートが処理される流れ

スクロールして1枚のツイートが画面に現れてから、ランキングに反映されるまでを追ってみましょう。

1
新しいツイートの出現に気づく 現場担当(content.js)は MutationObserver(変化の見張り役) を使い、ページに新しい部品が追加された瞬間を検知します。X全体を常にスキャンするのではなく、変化があった部分だけを見に行きます(これが軽さの秘訣)。
2
広告なら隠す そのツイートが広告だと判定したら xt-hidden の印を付けて、ここで処理終了。
3
タグと照合してチップを付ける 本文を読み、登録タグ・自動タグにヒットすれば、本文の上にチップを差し込み、背景をうっすら青くします。どれにもヒットせず、かつフィルタモードがONなら、ここで隠します。
4
単語を数える（ヒットしたツイートだけ） タグに一致したツイートに限り、本文を単語に分解して数えます。「Python関連の投稿の中で、他に何がよく出てくるか(=Django, 機械学習…)」を知るためです。無関係なツイートの単語はランキングに混ぜません。
5
まとめて司令塔に報告 数えた単語は毎回すぐ送らず、15秒ごとにまとめて司令塔(background.js)に送ります。司令塔は金庫の集計に足し込み、しきい値(初期20回)を超えた単語を自動タグに昇格させます。
6
設定画面に反映 ポップアップを開くと、司令塔から最新の集計を受け取り、頻出単語ランキングとして表示します。

日本語の「単語の切り分け」はどうやっている?

英語は単語の間にスペースがありますが、日本語は「今日はPythonの勉強」のように区切りがありません。そこで Chrome に内蔵された Intl.Segmenter という日本語分割機能を使っています(追加のライブラリ不要)。さらにノイズを減らすため、次のような語は数えません。

  • ひらがなを含む語 — 「食べる」「楽しい」「から」など動詞・形容詞・助詞はほぼ必ずひらがなを含むので、これを除くと残りはほぼ名詞(テーマ語)になります。
  • 英語の機能語 — of / at / to / and などは意味が薄いので除外。ただし AI / UI / DB のような短くても意味のある略語は残します。
  • 絵文字・記号・URL・メンション・「今日」などの一般語。

6つまずきポイントと、その解決の工夫

Xのような大規模サイトを相手にすると、素朴に作ると必ずハマる落とし穴があります。X Tagger が実際に踏んで直したものを紹介します。

問題なぜ起きるか解決の工夫
同じツイートを二重に数える Xは表示を軽くするため、画面外に出たツイートの「入れ物」を別のツイートに使い回す(仮想スクロール)。 各ツイートの固有URL(/status/…)を目印に記録し、中身が入れ替わったかを見分けて二重カウントを防ぐ。
タブを2つ開くと集計が壊れる 複数タブが同時に金庫へ書き込み、片方が上書きされる。 書き込みは司令塔ひとりに集約し、順番待ちの列で1件ずつ処理。
リセットしたのに集計が復活する 古いタブが、リセット前に数えた分を後から送りつけてくる。 集計に「世代ID(revision)」を付け、リセットで世代を更新。古い世代からの報告は受け取らない。
タグを変えても古い集計が残る 「Python」の集計に、別条件のときの単語が混ざる。 タグの内容から「署名(signature)」を計算。署名が変わったら、そのセットの集計をやり直す。
スクロールが重い 単語を保存するたびに、表示中の全ツイートを再判定していた。 「初回か / 設定・タグ・自動タグが変わったとき」だけ全体を再判定し、単なるカウント保存では画面に触れないように分離。
拡張を更新するとエラーが出る 更新後もページに残った古いプログラムが、消えた本体を呼ぼうとする。 本体が無効になったのを検知したら、見張りやタイマーを静かに停止する。

7ファイルの役割一覧

ファイル住む場所役割
manifest.json—設計図。名前・対象サイト・許可・使うファイルを宣言する。
content.jsXのページの中タイムライン監視、広告非表示、タグ付け、フィルタ、単語カウント。DOMを触る唯一の担当。
content.cssXのページの中チップの見た目、ハイライト、xt-hidden(非表示)などのルール。
background.jsブラウザの裏(常駐)集計の司令塔。報告を順番に処理し、セット別に保存、自動タグ昇格を判断。
statistics.js共通の道具箱単語の正規化、署名の計算、機能語リスト、司令塔への通信など共通ルール。
popup.html / popup.jsツールバーの設定画面タグ・セットの管理、頻出単語ランキング、設定、AI補助の操作。
tests/statistics.test.cjs開発時のみ集計・リセット・複数タブ・AIの挙動を自動検証するテスト(25件)。

8安全性 — 何を「できない」ようにしているか

拡張機能はページを書き換えられる強い力を持つ分、「何をしないか」も設計の大事な一部です。

  • 外部にデータを送らない: タグ・設定・単語の集計は、すべて chrome.storage(あなたのパソコンの中)に保存されます。外部サーバーへの送信はありません。ツイートの本文が外に出ることもありません。
  • AIもパソコンの中で完結: AI補助は Chrome に内蔵されたAI(Gemini Nano)を使い、モデルのダウンロード後は通信ゼロ。しかもAIに渡すのはタグ名や単語だけで、ツイート本文は渡しません。AIは提案するだけで、実際に設定を変えるかは常にあなたが決めます。
  • 動く範囲は x.com だけ: 設計図の matches で対象を x.com / twitter.com に限定しています。他のサイトでは一切起動しません。
  • やっているのは「表示の組み替え」だけ: Xのサーバーやアカウントには手を触れません。あなたのブラウザに届いた表示を、あなたのために見やすく並べ替えているだけです。
できないこと・限界: これはPCのChrome用です(スマホのChromeは拡張機能非対応)。またXが大規模にデザインを変えると、目印(data-testid)がずれて動かなくなる可能性があります。その場合はコード側の目印を直す必要があります。
